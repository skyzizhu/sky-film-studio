# 主题、讲解任务与可见证据

主题回答“讲什么”，task回答“观众需要理解什么关系”。direction.content/style/sound保持独立，新增可选task：mechanism（原理）、procedure（流程）、comparison（对比）、chronology（复盘）。历史内容可以讲原理，生活内容可以做对比，不把题材固定成一条叙事或配器。未配置task的旧片行为不变。

```sh
python3 engine/new.py /absolute/new-film --content science --style blueprint --sound none --task mechanism
python3 engine/direction.py --project /absolute/existing --content tutorial --style museum --task procedure
```

第二条仅产计划；--apply填默认，不会改写场景。省略--task会保留已有task。任务档案在direction-profiles.json的tasks，给出结构/证据/衔接/声音建议；不自动生成动作或改变音乐，不把字段齐全称为内容已验证。

## 把讲解落实到状态

每拍先写主角、输入/操作、观众可见的结果；如果状态来自前一拍，复用同一对象模型。可在beat中记录：

```json
{"evidence":{"subject":"同一根绳与负载","change":"右端下降，左端上升","result":"两端位移等量反向，绳长保持不变","event_ids":["pull"]},
 "events":{"pull":[1,4]},
 "transition_reason":"同一装置从全貌推近绳轮接触处"}
```

evidence可选；提供时预检检查subject/change/result非空、event_ids引用本拍事件。它只防缺字段与失效引用，不能证明画面真的展示了结果。关键动作由events与共享状态驱动，旁白短语需要精确同步时用本地词时码事件锚点；不按字数推断词时码。

- mechanism：检查连接、长度/数量/速比等约束，改变一个条件后结果由模型推导；理想条件与实物摩擦等边界可见。受力图与运动图分清，不把运动箭头当力箭头。
- procedure：物件ID在操作前后守恒；反馈由实际位置/状态计算。漏项应保留，再演示补回与复检，不能为了画面整齐凭空补齐物件。
- comparison：共同基线、尺度和时间可比，明确只变了哪些条件；不同配乐强度不能暗示尚无证据的优劣。
- chronology：用来源支持先后顺序，区分事实、推测与示意，不能用动画顺序证明历史因果。

## 由内容决定衔接

同物件、下一层解释：共享身份与绝对时间状态，沿关系推近/拉回；只淡换标注。操作到反馈：跟随物件落位，保持工作台参照。错误到恢复：保留错误现场，显示修复过程。换条件：先建立共同参照再改变条件。跨时空：明确标识后切换。fade/dissolve只是实现手段，不能修复断开的结构或重置的状态。转场前/中/后和动作停留都需采样，至少看一次连续片段。

## 声音来自事件与材料

先列可见声源，再决定是否需要发声。被动滑轮不默认套伺服电机声，普通手机拿起不自动“叮”。纸页可用paper，软质接触可用felt_contact，钥匙落位可小音量metal_contact；均标明合成示意，不冒充采样。抽象导线/标注声承担注意力引导，不称为物理声。放大特写按观察关系调整增益，左右声像对应声源位置；不逐拍交替声像。

配乐按任务留出解释与核对的停留；声音不能先于造成它的动作，结论不强制重击。首句、数字句、末句与动作接点分别听；ASR/响度/完整性检查不能代替主观试听。

## 跨主题验证

产品宣传另有 promotion 任务，适用范围与示例边界见 [product.md](product.md)。操作结果与确认反馈可分开：落位后短暂停留，再更新清单，下一操作给上一结果留观察时间。保持语义动作与口播对应；延后动作显式记录锚点 offset 并检查实际片段。手部接触、搬运、放下和撤手由同一物体状态推导；阴影位于投影平面，不随抬升贴在物体底下。

用适合各自任务的小案例验证，再把有效做法写回技能。至少保留：口播—事件—可见结果的对应、主要状态不变量、转场片段、实际编曲日志、事实/示意边界、人工试听状态。比较“是否看懂、动作是否成立、衔接是否有动机、声音是否帮助定位”，不只比较色板。自动指标不能冒充内容契合度评分。
