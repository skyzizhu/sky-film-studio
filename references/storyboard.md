# 分镜、构图与节奏

## 先确定要讲清楚的变化

每拍写：核心信息、口播句索引、主体、行为/关系、构图、出现事件、退出/衔接。不要机械把每个名词都变成图标。部件和素材选择见 [entities.md](entities.md)。

| 字段 | 含义 |
|---|---|
| id / start / end | 拍号及绝对秒；连续覆盖全片 |
| scene | storyboard.js 场景函数，运行时检查存在性 |
| sentences | cues 中的句子索引，不得遗漏、重复或越界 |
| energy | 0–1 配乐强弱 |
| sfx | 相对拍起点的事件，格式 [[t_rel,kind,gain]] |
| note | 主体/变化/层次/识别特征/参考依据 |

场景签名 `(ctx,t,l,beat)`：t 为全片秒，l=t-beat.start。实体 at、退出点及多数动效入场参数使用 l；绝对口播事件需减 beat.start。确认组件约定，不能把全片秒直接塞进局部 at。

## 内容预算与音乐

中文 TTS 约 4–4.5 字/秒可粗估：30 秒约 120 字，60 秒约 240 字，120 秒约 480 字。为停顿、图形理解和片尾留空间；实际以音频测长。超过预算优先压缩稿面，不靠持续加快语速。

开头尽快建立对象和问题，默认前三秒给出可理解的焦点；不强制炸字或数字对撞。章节切点可靠近乐句，动作重音跟语义。小节对齐是推荐工具，不能为填网格制造长空档。用户录音优先于音乐网格。相邻镜头可用构图变化、连续动作或视线关系衔接。

## 组件选择

| 信息 | 可选组件 |
|---|---|
| 核心词 | kineticWord / keywordMark，强调少量词即可 |
| 标签与说明 | textRise / typeOn / charFloat，确保停留可读 |
| 数值规模 | numCounter；事实值与口径来自 data.js/claims.json |
| 数值对比 | compareBars，长度按真实值比例，标注单位和基线 |
| 流程/步骤 | timelineN / stepIntro / flowPath |
| 清单 | checkList；不要为填空增加无关项目 |
| 文件/资质 | folder / stamp / seal |
| 产品界面 | phoneMock + phoneScreen；真实 UI 需参考 |
| 代码 | codePanel |
| 实物 | drawEntity / drawObj / 部件实体 |
| 收尾 | endingLine 或干净的主体停留，不强制金句 |

特效 shockwave/sparks/speedlines/rays 和拍首 wipe 都是可选强化。先保证观众看得懂发生了什么，再加冲击。静止、平滑慢推或脉冲都可使用，不要求每拍重击或每章数字。

## 布局与画幅

全片保持形状、字体、线宽、颜色语义一致；人物/物体跨镜头保持身份。前中背景可以有层次，但低信息镜头不必硬凑三层。一屏主焦点明确，实体数量由关系复杂度决定。

- 从实际 W/H 计算内容区，不以固定横屏坐标假装支持任意比例。
- 顶栏约 y=66；字幕基线有 timeline/进度时 H-160，否则 H-92；字幕可能有两行；时间轴约 H-72。内容须为实际字幕行数和平台遮挡留空间。
- 窄画幅优先单列，上下表现主体和说明；比较仍可并排，但要看实际字宽和识别度。
- punch 围绕画布中心缩放；必要内容的最终边界要用缩放后的坐标核对。不要依赖固定的横屏“安全坐标”覆盖所有画幅。
- 装饰边框挂 FILM.frame(ctx,t)，与 chrome 一样不跟随内容 punch；合法出血不能被边缘亮度扫描当成必然错误。

## 进度显示

film.json 的 progress:true/false 为显式配置；缺省自动条件为时长≥50s且拍数≥5。FILM.timeline 存在时优先显示时间轴。流程/旅程可用进度，故事/情绪类通常关闭，用户选择优先。

## 视觉检查

第一轮看构图、实物是否认得出、关键结构是否可信、文字/数据是否可读。修改后复查受影响镜头。抽取入场初期、中段、完成态、退出前后；连续看片段查部件跳动、锚点漂移、运动方向、动作节奏与口播事件。终检看完整成片或覆盖所有镜头的连续预览，再试听首句/数字句/末句。
